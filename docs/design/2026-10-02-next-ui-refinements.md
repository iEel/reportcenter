# ข้อเสนอ UI/UX หลังแก้ mockup ข้อ 1

วันที่ 2 ต.ค. 2026 · **ผู้ใช้อนุมัติข้อเสนอ 6 ข้อและ keyboard แล้ว; ปรับเฉพาะ local mock v3**

ข้อเสนอนี้เริ่มจากการทวน source ของ local mock กับ snapshot หลังแก้ข้อ 1, ผล browser รอบก่อน และ Handoff/docs ที่เกี่ยวข้อง ต่อมาผู้ใช้อนุมัติให้ปรับแบบตามข้อเสนอ จึงทำ [mockup v3](2026-10-02-mockups-v3/README.md) โดยไม่แก้ระบบจริง หลักฐานในส่วนท้ายเป็นฐานของข้อเสนอเดิม; สถานะผลตรวจใหม่แยกอยู่ด้านล่าง

## ลำดับที่แนะนำ

เริ่มทำความหมายและขอบเขตในหน้าหมวด/กลุ่มสิทธิ์ให้ชัด แล้วเก็บสรุปหน้าผู้ใช้และทางลัดในทะเบียน/รายงานมาตรฐาน เก็บ Esc/Tab/focus ตาม F4 ก่อนถือว่า mock พร้อมนำไปพัฒนาต่อ

| หน้า | สิ่งที่มีแล้ว / เหตุที่เสนอ | ข้อเสนอที่อนุมัติ |
|---|---|---|
| หมวดรายงาน | มีคำอธิบายว่าหมวดไม่เกี่ยวกับสิทธิ์แล้ว แต่หัวรายละเอียดใช้ Account ลอย ๆ; ฟอร์มเพิ่มหมวดยังอยู่เหนือรายละเอียดและปุ่มของหมวดเดิม | ใช้ “หมวดรายงาน: Account” และแยกบริบท “เพิ่มหมวดใหม่” ชัดเจน เช่น แยกการ์ดหรือซ่อนรายละเอียดเดิมระหว่างสร้าง |
| กลุ่มสิทธิ์ | มีรายการรายงาน/สมาชิกและสรุปเพิ่ม-ถอนแล้ว; tab นับ active แต่รายการตามหมวดรวม inactive | ใช้ “กลุ่มสิทธิ์: Account” และจำนวนแบบเดียวกัน เช่น “ใช้งาน 4 · ปิดใช้งานแต่เก็บสิทธิ์ 1”; ไม่ต้องเปลี่ยนชื่อข้อมูลจริงเพื่อแก้ความสับสน |
| กลุ่มสิทธิ์ขณะเลือกรายงาน | มีค้นหา เลือกที่แสดงอยู่ และสรุปจำนวนที่จะเพิ่ม/ถอนแล้ว | แสดง “เลือกทั้งหมด X · อยู่ในผลค้นหา Y” และเขียนขอบเขตปุ่มเลือกทั้งหมวดว่า “ในผลค้นหานี้” เมื่อมีตัวกรอง ลดการเข้าใจว่ารายการที่ซ่อนถูกยกเลิก |
| ผู้ใช้ | แบบมีสรุปรายงานจากกลุ่มและบริษัทที่เลือกอยู่แล้ว แต่แยกหลายส่วน | รวมเป็นสรุปสั้นก่อนปุ่มบันทึก เช่น “กลุ่มสิทธิ์ Account · รายงานใช้งาน 4 · บริษัท SNI, GRL” โดยแยกบริษัทต้นสังกัด AD ออกจากบริษัทที่อนุญาต ใช้ข้อมูลในฟอร์มเดิม ไม่เพิ่ม wizard |
| ทะเบียนรายงาน | คอลัมน์หมวดและกลุ่มสิทธิ์แยกอยู่แล้ว แต่กลุ่มที่เกิน 2 แสดง +N เป็น span/title | ให้ “+N กลุ่ม” เปิดดูชื่อครบได้ด้วยคลิกและคีย์บอร์ด แทนพึ่ง hover และคงตัวกรอง/ทางกลับหมวดที่มีอยู่ |
| รายงานมาตรฐาน | มีรายการโปรดและการเลือกรายงานก่อนบริษัทแล้ว แต่แถวทางลัดซ่อนหลังเลือกรายงาน | คงทางเข้ารายการโปรดหลังเลือก เพื่อสลับรายงานที่ใช้บ่อยได้ง่าย คงลำดับเลือกรายงาน → บริษัท/เงื่อนไขเฉพาะรายงาน → ดึงข้อมูล → ส่งออก |

สำหรับแท็บเทียบกลุ่ม ให้ระบุว่าปัจจุบันนับเฉพาะรายงานที่ใช้งาน และอย่าใช้เปอร์เซ็นต์เดียวแทนข้อสรุปว่าสิทธิ์ทุกอย่างเหมือนกัน เป็นการทำข้อความให้ตรงขอบเขตเดิม ไม่เพิ่มกติกายุบกลุ่มอัตโนมัติ

## สถานะหลังปรับ v3

ทำทั้ง 6 ข้อใน [page-categories.js](2026-10-02-mockups-v3/page-categories.js), [page-roles.js](2026-10-02-mockups-v3/page-roles.js), [page-users.js](2026-10-02-mockups-v3/page-users.js) และ [page-reports.js](2026-10-02-mockups-v3/page-reports.js) พร้อมปรับ keyboard/focus ใน [core.js](2026-10-02-mockups-v3/core.js) โดยรักษา draft guard จากรอบแก้ข้อ 1 และ flow AD/Local เดิมของ mock

Node regression ของ mock **42 passed**; `npm test` รอบนี้รายงาน **16 files, 228 passed, 2 todo** โดยนับ tests ซ้ำจาก `.claude` worktree ที่มีอยู่ด้วย จึงไม่ใช่ 228 กรณีที่ไม่ซ้ำกัน Browser QA desktop ผ่าน flow หมวด/กลุ่ม/ผู้ใช้/รายงานและ keyboard ที่ระบุใน [README v3](2026-10-02-mockups-v3/README.md) พร้อมภาพ 7 ภาพ; viewport สุดท้าย 1600 × 709, console warning/error 0 ยังไม่ได้ตรวจ mobile README ระบุวิธีเปิด ข้อมูลสมมติที่ reset เมื่อ refresh และขอบเขตผลตรวจไว้ด้วย

การอนุมัตินี้ครอบคลุมแบบในเครื่อง ไม่ใช่ production implementation, deployment หรือ UAT ข้อแตกต่าง F7 เรื่องกฎเงื่อนไข, `.xlsx` ใน mock เทียบกับ `.xlsb`/`.csv` จริง, ลบกำหนดการ, mapping ของรายงานปิดใช้งาน และ enforcement ฝั่ง API ยังคงเดิม
