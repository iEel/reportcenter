## 2026-10-06 — ส่งออก Excel เป็น .xlsx แบบบีบอัด แทน .xlsb

**สถานะ:** ผู้ใช้สั่ง “เปลี่ยนเป็น xlsx เลย”; แก้ใน branch `claude/export-format-xlsb-xlsx-592f13` ยังไม่ merge/deploy

- ทุกจุดที่เขียน Excel (หน้ารายงานมาตรฐาน, Template, Audit log, อีเมลตั้งเวลา cron, รันกำหนดการด้วยมือ) ใช้ `src/lib/excel-export.js`: `bookType: 'xlsx'`, `compression: true`, `bookSST: true`
- ไฟล์แนบอีเมลระบุ MIME ของ xlsx ทั้งสองเส้นทาง (เดิม cron แนบ `.xlsb` แต่ระบุ MIME ของ xlsx และรันด้วยมือไม่ระบุ)
- รายงานหนัก (`IsHeavy`) ยังส่งออก CSV แบบ stream ตามเดิม

**เหตุผลและหลักฐาน:** วัด SheetJS 0.18.5 (รุ่นใน `package.json`) ด้วยข้อมูลสมมติ 10 คอลัมน์ใน Chrome 152: 50,000 แถว xlsb ใช้ 60.5 วินาที / 12.1 MB ส่วน xlsx+compression+bookSST ใช้ 3.3 วินาที / 6.6 MB และหน้าเว็บค้างระหว่างเขียน xlsb; ข้อความเดิมใน Handoff ว่า xlsb เล็กกว่า 50–70% เทียบกับ xlsx ที่ไม่บีบอัดเท่านั้น xlsb ยังเป็นชนิดที่เก็บมาโครได้ ซึ่งระบบกรองอีเมลบางแห่งบล็อก และ Google Sheets เปิดไม่ได้

**ขอบเขต:** ไม่แก้การใช้หน่วยความจำ (ยังโหลดข้อมูลทั้งหมดเข้าเบราว์เซอร์/หน่วยความจำ server เหมือนเดิม) และยังไม่ได้วัดเวลาเปิดไฟล์ใหญ่มากใน Excel ซึ่ง xlsb อาจเร็วกว่า

## 2026-10-06 — สิทธิ์รายงานมาจากกลุ่มสิทธิ์อย่างเดียว เลิกใช้ตัวเลือก “ทุกคน (Public)”

**สถานะ:** ผู้ใช้เลือกแบบ ก. (“เอาแบบ ก.”); แก้ใน branch `claude/review-p2-p1-fixes`

- หน้าสร้าง/แก้รายงานไม่มีตัวเลือก “ทุกคน (Public)” แล้ว แสดงรายการกลุ่มสิทธิ์ให้เลือกเสมอ ไม่เลือกกลุ่ม = เห็นเฉพาะผู้ดูแลระบบ
- `POST /api/admin/reports` บันทึกกลุ่มที่เลือกเสมอ (เดิมข้ามการบันทึกเมื่อ `IsPublic` เป็นจริง ทำให้รายงาน “Public” เห็นได้แค่ Admin); หน้าเว็บส่ง `IsPublic: false`
- คอลัมน์ `Reports.IsPublic` ยังอยู่เพื่อประวัติ/เวอร์ชัน แต่ไม่ให้สิทธิ์ใด ๆ; รายงานเดิมที่เคยตั้ง Public จะเห็นคำแนะนำในหน้าแก้ให้เลือกกลุ่ม

**เหตุผลและหลักฐาน:** ทวนโค้ดแล้ว `IsPublic` ไม่ถูกใช้ในจุดตรวจสิทธิ์ใดเลย (`available`, `execute`, `execute-async`, `parameters`, `search-param` ใช้ `ReportRoleMapping`) ป้าย “ทุกคน (Public)” จึงขัดกับพฤติกรรมจริง (ข้อ 23 ใน [รีวิว implementation](audits/2026-10-06-implementation-review/README.md)); แบบ ข. (ให้ Public เปิดทุกกลุ่ม) ต้องแก้จุดตรวจสิทธิ์หลายจุดและกระทบความปลอดภัย

**ขอบเขต:** ไม่ migrate ข้อมูลเดิม ไม่ลบคอลัมน์; รายงานที่เคยตั้ง Public และยังไม่มีกลุ่ม จะยังเห็นเฉพาะ Admin จนกว่าจะเลือกกลุ่ม (พฤติกรรมเดิม)

## 2026-10-06 — รายงานที่มีประวัติใช้งานไม่ลบถาวร ให้ปิดใช้งานแทน

**สถานะ:** ผู้ใช้เลือกแบบ ก. (“เอาแบบ ก. คงไว้”); ไม่เปลี่ยนโค้ดเพิ่มจากการแก้ P0

- `DELETE /api/admin/reports/[id]` ไม่ลบหรือปลดการอ้างอิงใน `ActivityLogs` เมื่อมีข้อมูลอื่นอ้างถึงรายงาน (FK error 547) ระบบ rollback ทั้งหมดและตอบ 409 ข้อความไทยให้ปิดใช้งานรายงานแทน
- ไม่ใช้แนวทางตั้ง `ActivityLogs.ReportId = NULL` แบบที่ลบผู้ใช้ทำกับ `UserId` เพื่อให้ประวัติการใช้งานยังผูกกับรายงานครบ
- ตารางที่ไม่มี FK หรือเป็นข้อมูลประกอบของรายงานโดยตรง (ตัวแปร สิทธิ์ รายการโปรด) ยังถูกลบใน transaction เดียวกันตามเดิม

**เหตุผลและหลักฐาน:** ผู้ตรวจพบว่า `scripts/create_activity_logs.sql:7` กำหนด FK จาก `ActivityLogs.ReportId` ไป `Reports` และระบบบันทึกแถวที่อ้างรายงานเมื่อสร้าง แก้ หรือรัน จึงลบถาวรไม่ได้แทบทุกรายงานถ้าฐานจริงมี FK นี้ ผู้ใช้เลือกคงประวัติไว้ ดู [ผลการแก้ P0](audits/2026-10-06-implementation-review/README.md#ผลการแก้-p0-6-ตค-2026)

**ขอบเขต:** ยังไม่ได้ตรวจ FK ในฐานจริง; `DELETE /api/admin/reports/bulk` ยังไม่ได้ปรับให้ตอบ 409 แบบเดียวกัน

## 2026-10-06 — ไม่จัดลำดับงาน accessibility สำหรับเทคโนโลยีช่วยเหลือ

**สถานะ:** ผู้ใช้ยืนยันขอบเขตผู้ใช้งาน; ใช้จัดลำดับผลรีวิว ไม่ได้แก้โค้ด

- ผู้ใช้แจ้งว่า “ระบบไม่มีสำหรับผู้พิการ” จึงไม่จัดข้อที่กระทบเฉพาะโปรแกรมอ่านหน้าจอหรือการสั่งงานด้วยเสียงเป็นงานที่ต้องทำ เช่น aria-live ของ toast, ชื่อ accessible ของปุ่ม, semantics ของ tabs/listbox/typeahead
- ข้อที่กระทบผู้ใช้ทุกคนยังคงไว้ในฐานะ UX ทั่วไป: ป้าย “ใช้งาน” ที่กดแล้วระงับผู้ใช้, ปุ่มหลักหน้ากลุ่มสิทธิ์ที่หายตอน hover; ส่วน contrast ของปุ่มส้มและ focus หลุดหลังบันทึกลดเป็นงานเก็บรายละเอียด
- ไม่เพิ่มข้อกำหนด WCAG เป็นเกณฑ์ผ่านของงาน UI ในโปรเจคนี้ จนกว่าผู้ใช้จะเปลี่ยนขอบเขต

**เหตุผลและหลักฐาน:** คำชี้แจงผู้ใช้ต่อข้อ a11y ใน [รีวิว implementation 06ec60a](audits/2026-10-06-implementation-review/README.md) ซึ่งมีข้อที่อิงโปรแกรมอ่านหน้าจอ/เสียงหลายข้อ (ข้อ 8–10, 26–28, 31, 41, 45, 55, 58)

**ขอบเขต:** ไม่ใช่การยกเลิกพื้นฐานที่ช่วยทุกคน เช่น label ของช่องกรอก, keyboard ปกติ (Esc/Enter/Tab) และความอ่านง่ายของข้อความ ข้อเหล่านั้นยังพิจารณาตามผลต่อผู้ใช้ทั่วไป

## 2026-10-01 — รักษาความหมายการเรียกรายงานและเงื่อนไขเฉพาะ Report

**สถานะ:** ผู้ใช้ยืนยัน workflow; ยังไม่อนุมัติหรือทำ implementation

- ปุ่มดึงข้อมูลหมายถึงเรียกรายงานจริง และส่งออกรายงานที่เรียก ไม่เปลี่ยนคำเป็น “แสดงตัวอย่าง”
- แต่ละ Report กำหนดเงื่อนไขต่างกันจาก definition ไม่ถือว่า CompanyCode ซ้ำกับบริษัท และไม่ปรับ/เติมเงื่อนไขอัตโนมัติโดยไม่ตรวจความหมายเฉพาะรายงาน
- เมื่อเปลี่ยน Report/เงื่อนไข พนักงานเรียกรายงานใหม่ตามงาน ผู้ใช้ไม่ต้องการข้อเสนอแถบเตือนเงื่อนไขเปลี่ยน จึงถอนข้อเสนอนี้
- ตรวจทุกหน้าก่อนสรุป UX และคงคำขอ “ยังไม่แก้ไข” การบันทึก audit/wiki ไม่ใช่อนุมัติแก้ระบบ

**เหตุผลและหลักฐาน:** คำชี้แจงผู้ใช้ร่วมกับหน้าสร้าง Report/User และ source ที่นิยามเงื่อนไขแยกต่อรายงาน: `src/app/(dashboard)/admin/reports/new/page.tsx:55,406`, `src/app/api/admin/reports/route.js:57`, `src/app/(dashboard)/reports/standard/page.tsx:113,487,528` ผลทวนครบใน [UI/UX audit](audits/2026-10-01-ui-ux/README.md)

**ข้อจำกัด:** เจตนาส่งออกไม่ใช่หลักฐาน snapshot consistency; Standard มี query ใหม่ใน export ส่วน Template ปกติใช้ผลที่โหลดมา ยังไม่ทดสอบ runtime และไม่เพิ่มข้อกำหนด stale banner จากความต่างนี้
