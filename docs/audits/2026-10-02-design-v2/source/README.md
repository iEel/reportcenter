- เปิดในเครื่อง: ต้องเปิดผ่าน HTTP server เพราะ `index.html` เป็นเนื้อหาที่ Artifact ห่อ skeleton ให้ตอนเผยแพร่

## Brief ที่ผู้ใช้อนุมัติ

- รูปแบบหน้าเว็บกดได้จริง คงหน้าตาเดิม (sidebar กรมท่า ปุ่มน้ำเงิน พื้น slate) แต่ใช้ส่วนประกอบชุดเดียวทุกหน้า
- ใส่วิธีทำงานใหม่ได้ โดยติดป้าย “ใหม่” = ยังไม่มีในระบบจริงและต้องพัฒนาฝั่ง API ด้วย
- 1 ชุดที่แนะนำ ยกเว้นกลุ่มสิทธิ์มี 2 ทางเลือก: A ตารางรวม รายงาน × กลุ่ม / B รายการ + รายละเอียด (รอบ 2 ผู้ใช้เลือก B)
- คงความหมายปุ่ม “ดึงข้อมูล” (เรียกรายงานจริง) และเงื่อนไขเฉพาะแต่ละรายงานตาม `docs/12_DECISION_LOG.md` ใน main checkout

## รอบที่ 2 — ตามคำขอผู้ใช้ (1 ต.ค. 2026, Artifact version 2)

- **เพิ่มผู้ใช้เป็นป๊อปอัป** กว้าง 640px แทนแผงด้านข้าง ผลค้น AD แสดงในป๊อปอัปเลย รายการรายงานพับไว้เป็นบรรทัดสรุป ปิดขณะกรอกค้างจะถามก่อนทิ้ง ส่วนดู/แก้ผู้ใช้เดิมยังเป็นแผงด้านข้าง
- **เอาปุ่มพิมพ์ออกจากรายงานมาตรฐาน:** ระบบจริงมีปุ่ม Print / PDF ที่เรียก `window.print()` (`src/app/(dashboard)/reports/standard/page.tsx:606`) และตารางแบ่งหน้าฝั่ง server 25/50/100 แถว (`:37,713`) จึงพิมพ์ได้แค่หน้าที่แสดงอยู่ เหลือ “ส่งออก Excel” ที่ได้ข้อมูลครบ การเอาออกจากระบบจริงยังไม่ได้ตัดสิน
- **กลุ่มสิทธิ์ใช้แบบ B** ตัดตารางรวมออก แล้วเสนอเพิ่ม (ป้าย “ใหม่”): ปุ่ม “เพิ่มสมาชิก” ย้ายผู้ใช้มากลุ่มนี้ได้หลายคน, แท็บ “เทียบกับกลุ่มอื่น” ที่ชี้กลุ่มที่รายงานใกล้เคียงที่สุดเพื่อหากลุ่มซ้ำ, ป้าย “ไม่มีสมาชิก/ไม่มีรายงาน” ในรายการกลุ่ม

## รอบที่ 3 — dropdown และปุ่ม ⋯ (Artifact version 3)

- ผู้ใช้เห็นว่า dropdown (เช่น กลุ่มสิทธิ์ในหน้าผู้ใช้) เรียบเกินไป → เปลี่ยน `<select>` ทุกตัวเป็น dropdown แบบมีรายละเอียด (`dd()` ใน `core.js`): ตัวเลือกมีไอคอน/จุดสี/รหัสบริษัท บรรทัดอธิบาย จำนวน และเครื่องหมายเลือก แบ่งหัวข้อได้ ค้นหาได้เมื่อมีตัวเลือกมาก ตัวกรองที่กำลังใช้อยู่เปลี่ยนสีพื้น เลือกด้วยลูกศร/Enter/Esc ได้
- ผู้ใช้ขอเอาปุ่ม ⋯ ออกทั้งหมด → คำสั่งรายแถวเป็นปุ่มที่เห็นตรง ๆ (แก้ไข + ไอคอนพร้อมคำอธิบายเมื่อชี้); ลบหมวด / เปลี่ยนชื่อ / ลบกลุ่ม อยู่บนหัวแผง; ลบกลุ่มที่ยังมีสมาชิกจะบอกเหตุผลและพาไปดูสมาชิก
- ถ้าทำจริงต้องมีคอมโพเนนต์ dropdown กลางที่รองรับคีย์บอร์ดและ screen reader ครบ (เขียนเองหรือใช้ไลบรารี) ยังไม่ได้ตัดสิน

## รอบที่ 4 — ตัวเลือกรายงานและบริษัท (2 ต.ค. 2026, Artifact version 4)

- ผู้ใช้ถามว่าตัวเลือกบริษัทหายไปไหน → ไม่ได้หาย แต่ทั้ง mockup และระบบจริงแสดงช่องบริษัทเฉพาะหลังเลือกรายงาน (`src/app/(dashboard)/reports/standard/page.tsx` วางช่องบริษัทในส่วนตัวกรอง และตั้งค่าเริ่มต้นเป็นบริษัทแรกที่อนุญาต `:51–58,477`) จึงดูเหมือนไม่มี
- ปรับให้บริษัทเป็นขั้นแรกและเห็นตลอด เป็นปุ่มเลือก SNI / GRL / SALOG (ถ้ามีบริษัทเดียวแสดงเป็นป้าย) ใช้กับทุกรายงานและจำบริษัทล่าสุด
- ตัวเลือกรายงานต่อยอดจาก spec ที่อนุมัติแล้ว (`docs/superpowers/specs/2026-08-14-standard-report-selector-design.md`: combobox เดียว รายการโปรด จัดกลุ่มตามหมวด ไม่มีเครื่องหมายถูก) แล้วเพิ่ม: ช่องใหญ่ขึ้น ไฮไลต์คำที่ค้น ดาวกำกับรายงานโปรด ปุ่มลัดท้ายรายการ ปุ่ม × ล้าง กด `/` เพื่อค้น และแถว “ใช้ล่าสุด”
- “ใช้ล่าสุด” spec เดิมจัดไว้นอกขอบเขตเพราะต้องมีที่เก็บประวัติ; ระบบตอนนี้ไม่บันทึกการเรียกรายงาน (ActivityLogs ของ execute บันทึกเฉพาะ BLOCKED_QUERY) จึงต้องเพิ่มที่เก็บ (เช่นในเบราว์เซอร์หรือ API ใหม่) ยังไม่ได้ตัดสิน
- ขัดกับ spec 1 จุด: spec ใช้ “อื่น ๆ” กับรายงานไม่มีหมวด ส่วน mockup ใช้ “ยังไม่จัดหมวด” ให้ตรงหน้าผู้ดูแล ต้องยืนยันคำที่จะใช้

## สิ่งที่อิงจากระบบจริง

ดูหน้าจริงจาก session ผู้ดูแลที่ localhost:4000 เมื่อ 1 ต.ค. 2026 และอ่านโค้ด `src/app/(dashboard)/reports/standard/page.tsx`, `admin/reports`, `admin/categories`, `admin/users`, `admin/roles` พร้อม API คู่กัน ชื่อรายงานในข้อมูลสมมติตามรายการจริง ส่วนผู้ใช้ จำนวน และการผูกสิทธิ์เป็นข้อมูลสมมติ ขนาดใกล้ของจริง (11 กลุ่ม, ~26 รายงาน, 19 ผู้ใช้, 3 บริษัท)

ข้อค้นพบที่ mockup แก้ให้เห็น อ้างจากการตรวจรอบเดียวกัน (วิกิ `rc-admin-pages-ux-recheck-20261001`): Role Admin ถูกเปลี่ยนชื่อได้, ระงับ/เปลี่ยนกลุ่มตัวเองได้, รีเซ็ตรหัสผู้ใช้ AD ไม่มีผล, รหัสเริ่มต้นร่วม, โหมดมืดของหน้ารายงานมาตรฐานเป็นตัวขาวบนพื้นขาวเมื่อ Windows ตั้งโหมดมืด (Tailwind `dark:` ใช้ media query ขณะที่ปุ่มสลับธีมใช้ class `.dark`)

## ตรวจแล้ว / ยังไม่ได้ตรวจ

- ตรวจแล้ว: `node --check` ทุกสคริปต์ผ่าน; เปิดทั้ง 5 หน้าที่ 1440×900 และ 390×844 ไม่มี console error; ทุกหน้าไม่เลื่อนแนวนอนที่ 390px; ตรวจโหมดมืดหน้ารายงานมาตรฐานและฟอร์มผู้ใช้; Impeccable detector ไม่พบปัญหา
- ยังไม่ได้ตรวจ: screen reader, contrast วัดจริงทุกคู่สี, การใช้คีย์บอร์ดครบทุกเส้นทาง
- ไม่ใช่หลักฐานว่าระบบจริงทำงานแบบนี้ ป้าย “ใหม่” ทุกจุดต้องออกแบบ API และทดสอบก่อนใช้จริง
